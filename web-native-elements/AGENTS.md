# Native element rules

- `web-native-elements` implements only the reached read-only React Native element value surface. It is not a browser DOM tree, renderer, layout engine, Android view registry, or mutation API.
- Keep each `ReactNativeElement` wrapper final and compact: one shared `NativeElementContext` reference, one primitive renderer identity, and one optional lazily allocated `HTMLCollection` reference required by the `[SameObject]` `children` contract. Do not add a per-element runtime reference, geometry scratch fields, parent fields, child arrays, maps, locks, atomics, tasks, or lifecycle registry slots.
- One `NativeElementContext` belongs to one `RuntimeInstance` and renderer host. It directly owns the reusable primitive rectangle, offset, and relation sinks and one shared read-kind guard. Reject nested cross-kind reads and stale sink use.
- A successful rectangle, offset, or relation host read writes exactly one result synchronously. A false result writes none. The host must not retain a sink, invoke generated language code, or schedule another callback while a sink is active.
- The renderer owns the stable public-wrapper store. `createElement(identity)` must return the same wrapper for the same exact mounted identity, allocate exactly one wrapper on a cache miss, and reject wrappers belonging to another context or identity. Do not add a core-owned generic map or boxed identity.
- `isSameNode` is the owner-confined reference-identity operation. `contains` accepts the selected element carrier or null, returns true for self even when detached, returns false across renderer contexts, and walks current primitive parent identities with O(1) cycle-detection state. It must not allocate ancestor sets, arrays, iterators, or intermediate public wrappers.
- `children` returns one lazy same-object live `HTMLCollection`. The collection retains no child snapshot or wrapper array. `length`, `item`, and `namedItem` walk the current primitive relation snapshot and may allocate only the final requested public wrapper on a cache miss. The reached React Native profile exposes IDs but no separate HTML `name` attribute, so supported collection names are non-empty IDs in current child order.
- `getBoundingClientRect()` includes transforms and returns one new non-live `DOMRect`. `offsetWidth`, `offsetHeight`, `offsetTop`, and `offsetLeft` use ECMAScript `Math.round`, including negative zero, NaN, and infinities.
- `offsetParent` returns the renderer's exact published parent wrapper. A hidden renderer root, unavailable offset, stale generation, or missing public wrapper returns null while a root-relative successful snapshot may still expose top and left.
- Parent, child endpoint, and sibling getters resolve exact-generation identities through the renderer's public-wrapper store. A stale or unavailable relationship returns null. `childElementCount` is an allocation-free primitive read and never implies node-level traversal or a collection snapshot.
- Client and scroll metric getters are raw allocation-free scalar reads. Do not round or normalize fractions, signed zero, NaN, infinities, or negative values in the core.
- Renderer identities are opaque generation-safe `long` values. They are never exposed as JavaScript numbers and never resolved through a core-owned generic map.
- The renderer owns connectivity, tag names, ids, public-instance lookup, committed-layout timing, offsets, element relations, transforms, coordinate conversion, and platform view lifecycle. The core must not retain an Android `View` or poll layout.
- Callback-based `measure`, `measureInWindow`, `measureLayout`, remaining node-level traversal and collections, `compareDocumentPosition`, events, focus, pointer capture, scroll mutation, text content, native property mutation, and collection iteration/indexer lowering require separate reached contracts and conformance.
- Do not add Android, React Native implementation, reflection, networking, serialization, generic collection, executor, Future, coroutine, Handler, or `Runnable` dependencies to production.
